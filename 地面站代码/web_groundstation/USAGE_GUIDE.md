## 二、第一部分：配合真机部署

### 2.1 环境准备

**硬件要求：**
- 一台运行 Ubuntu 20.04 的笔记本电脑（作为地面站）
- 该电脑需要与机载计算机（192.168.10.3）在同一局域网内
- 推荐通过网线直连或专用 WiFi 路由器组网

**软件安装（在 Ubuntu 20.04 终端中执行）：**

```bash
# 第1步：确认 Python 版本 ≥ 3.8
python3 --version
# 输出应为: Python 3.8.x 或更高

# 第2步：安装 pip3（如果没有的话）
sudo apt update
sudo apt install -y python3-pip

# 第3步：安装 Python 依赖
cd web_groundstation/
pip3 install -r requirements.txt
# 或者使用 --user 避免权限问题:
pip3 install --user -r requirements.txt

# 第4步：验证安装
python3 -c "import flask; import flask_socketio; print('依赖安装成功')"
# 输出应为: 依赖安装成功
```

**地图文件准备：**

```bash
# 将您的场地地图图片（任意分辨率）重命名为 map.png
# 放入 web_groundstation/ 目录
cp /where/your/map/is/located.png ./web_groundstation/map.png

# 地图会被前端自动缩放至 Canvas 360×280 区域显示
```

### 2.2 网络配置

**地面站电脑需要能够访问机载计算机的 IP 地址。**

```bash
# 第1步：查看本机 IP
ip addr show
# 找到 eth0/wlan0 对应的 IP，例如 192.168.10.100

# 第2步：测试与机载计算机的连通性
ping 192.168.10.3
# 应该看到：64 bytes from 192.168.10.3: icmp_seq=1 ttl=64...
# 如果 ping 不通，说明网络未连通，需要检查：
#   - 网线是否插好
#   - IP 地址段是否相同（都是 192.168.10.x）
#   - 防火墙是否关闭或放行
```

**如果 ping 不通，先不要继续，排查网络问题后再进行下一步。**

### 2.3 启动流程（分步图解）

#### 步骤 1：启动机载端所有服务

```bash
# —— 在机载计算机上执行 ——
cd ~/drone_ws/
source /opt/ros/noetic/setup.bash   # ROS环境
source install/setup.bash            # 工作区环境

# 启动全部节点（包括 LandScreenNode TCP 8001）
roslaunch offboard start_drone.launch.py
```

**确认机载端就绪的标志：**
- 终端中看到 `[land_screen]` 节点的日志输出
- 用 `ss -tlnp | grep 8001` 确认端口 8001 正在监听

#### 步骤 2：启动地面站 Web 服务

```bash
# —— 在地面站电脑上执行 ——
cd ~/web_groundstation/

# 方法A：使用启动脚本（推荐）
chmod +x launch_groundstation.sh
./launch_groundstation.sh

# 方法B：手动启动
python3 app.py --host 0.0.0.0 --port 5000
```

**启动成功标志：**
```
15:30:01 [GroundStation] INFO: 正在初始化地面站核心模块...
15:30:02 [LandScreen] INFO: Connected to server
15:30:02 [GroundStation] INFO: 地面站 Web 服务器启动: http://0.0.0.0:5000
15:30:02 [GroundStation] INFO: 请在浏览器中打开上述地址，按 F11 进入全屏模式
```

如果看到 `Connected to server`，说明与机载端 TCP 8001 连接成功！

#### 步骤 3：打开浏览器

```bash
# 方法A：在地面站本机浏览器打开
firefox http://localhost:5000

# 方法B：从其他电脑/平板访问（替换为地面站IP）
# 浏览器打开: http://192.168.10.100:5000
```

按 **F11** 进入全屏模式，即可获得与原 Qt 全屏完全一致的操作体验。

### 2.5 完整操作流程

**场景：一次完整的飞行任务操作**

#### 阶段 1：系统初始化

```
1. 确认机载端已启动（LandScreenNode 就绪）
2. 启动地面站 Web 服务
3. 浏览器打开 → F11 全屏
4. 观察连接状态从 "未连接" → "已连接"  ✅
5. 观察地图上出现红色规划路径 + 箭头  ✅
```

#### 阶段 2：设置禁飞区

```
1. 在 A 行点击网格按钮，例如点击 "3"
   → A3 按钮变为蓝色选中状态（高亮）
   
2. 在 B 行点击网格按钮，例如点击 "5"
   → B5 按钮变为蓝色选中状态
   → 两个按钮自动恢复白色
   → F1 标签从 "NULL" 变为 "禁飞区1（A3,B5）"
   
3. 重复操作设置 F2：
   A 点击 "7" → B 点击 "2"
   → F2 标签变为 "禁飞区2（A7,B2）"
   
4. 重复操作设置 F3：
   A 点击 "1" → B 点击 "6"
   → F3 标签变为 "禁飞区3（A1,B6）"
```

此时界面显示：
```
禁飞区1（A3,B5）
禁飞区2（A7,B2）
禁飞区3（A1,B6）
```

#### 阶段 3：发送禁飞区

```
1. 确认三个禁飞区标签正确
2. 点击 "发送" 按钮
   → 地面站提取 F1/F2/F3 中的 A/B 坐标
   → 通过 TCP 8001 发送给机载端
   → 机载端转换为 /nofly_zone ROS 话题
   
   # 在机载终端可以看到：
   # [land_screen] 收到禁飞区: F1(A3,B5) F2(A7,B2) F3(A1,B6)
```

**如果禁飞区设置错误：**
```
点击 "取消" 按钮
→ 三个标签全部重置为 "NULL"
→ 重新选择 A/B 网格，重新点击 "发送"
```

#### 阶段 4：启动任务

```
1. 确认禁飞区已经发送（标签非 NULL）
2. 点击 "启动" 按钮
   → 地面站设置 dataSend["launch"] = True
   → 通过 TCP 8001 发送 {"f1x":3,...,"launch":true}
   → 机载端发布 /launch = True
   → 无人机开始执行路径规划飞行
```

**安全保护：**
```
如果直接点击 "启动"（未设置任何禁飞区）：
→ 弹出警告弹窗 "没有禁飞区信息，无法启动"
→ 不会发送启动指令
```

#### 阶段 5：任务进行中 — 观察目标信息

```
飞行过程中，机载端以 10Hz 发送目标检测数据：
  {"tx":-0.75, "ty":0.25, "tn":"red", "planner":[...]}

地面站实时更新：
  → 底部目标汇总标签更新为最新目标信息
    例: "red, A:6, B:1, 数量：1"
     
  → 点击 "显示目标信息" 按钮
    打开目标信息页面，显示：
    ┌──────────────────────────────────────┐
    │ 目标详细信息          │ 目标统计      │
    │ ┌──────────────────┐  │ red: 3       │
    │ │ red  A6  B1  N1  │  │ blue: 2      │
    │ │ blue A7  B2  N1  │  │ green: 2     │
    │ │ red  A7  B2  N2  │  │ yellow: 1    │
    │ │ green A6  B3  N1  │  │ orange: 1    │
    │ │ ...               │  │ purple: 1    │
    │ └──────────────────┘  │ 总计: 10     │
    └──────────────────────────────────────┘
    
  → 点击 "救援" 按钮
    → 选中的目标位置更新到 SharedData.target_chosen_
    → 弹出确认提示 "已选择救援目标: red"
```

### 2.6 常见问题与排查

| 问题 | 可能原因 | 解决方法 |
|------|---------|---------|
| 连接状态始终显示 "未连接" | 网络不通 | `ping 192.168.10.3` 确认连通 |
| | 机载端未启动 | 登录机载 `ss -tlnp \| grep 8001` |
| | 防火墙拦截 | `sudo ufw allow 8001` |
| | 独立测试忘记改 IP | 加上 `--server-ip 127.0.0.1` 参数 |
| 地图显示黑屏 | map.png 缺失 | 复制地图文件到程序目录 |
| | 地图路径不对 | `python3 app.py --map /path/to/map.png` |
| 目标汇总不更新 | 机载端未发送目标 | 检查 `/target_pose` ROS 话题 |
| 禁飞区发送后无反应 | 机载端未收到 | 检查机载终端日志 |
| 浏览器白屏 | JavaScript 加载失败 | F12 打开开发者工具查看错误 |
| | Socket.IO CDN 被墙 | 将 index.html 中 CDN 地址替换为国内镜像 |
| MockServer 发送后前端无更新 | 地面站未连接到模拟端 | 确认启动时加了 `--server-ip 127.0.0.1` |

## 三、第二部分：无真机独立测试

如果你没有机载计算机/无人机，或者想在部署前先验证地面站功能是否正常，
可以使用项目自带的 **`mock_tcp_server.py`** 模拟机载端行为进行完整测试。

### 3.1 测试环境搭建

**最低要求：一台电脑即可（支持 Windows / macOS / Ubuntu）**

```bash
# 第1步：安装 Python 依赖（和真机部署相同）
cd web_groundstation/
pip3 install -r requirements.txt

# 第2步：准备地图图片（可以用任意 360×280 的图片代替）
# Ubuntu:
cp /usr/share/backgrounds/warty-final-ubuntu.png ./map.png
# 或者创建一个纯色测试图:
python3 -c "
from PIL import Image
img = Image.new('RGB', (360, 280), color='lightgreen')
img.save('map.png')
"
```

**打开第1个终端窗口：**

```bash
cd web_groundstation/
python3 mock_tcp_server.py
```

**启动成功输出：**

### 3.3 启动地面站 Web 服务

**打开第2个终端窗口：**

```bash
cd web_groundstation/

# 独立测试时，必须指定 --server-ip 为 127.0.0.1
# 因为 mock_tcp_server.py 运行在本机上
python3 app.py --host 127.0.0.1 --port 5000 --server-ip 127.0.0.1
```

> **说明：** `--server-ip` 告诉地面站去哪里连接机载端（或模拟端）。真机部署时不需要此参数（默认 `192.168.10.3`）。

### 3.6 手动发送 JSON 测试

如果你想更精确地控制测试输入，可以绕过 MockServer，用以下方式手动发送数据：

#### 方法 1：使用 Python 脚本发送

```python
# manual_send_test.py
import socket
import json
import time

sock = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
sock.connect(("127.0.0.1", 8001))

# 发送第一次数据（含完整 planner 路径）
data1 = {
    "tx": -0.75,
    "ty": 0.25,
    "tn": "red",
    "planner": [
        {"x": 0.25, "y": 0.25},
        {"x": 1.25, "y": 0.25},
        {"x": 2.25, "y": 0.75},
        {"x": 3.25, "y": 1.25},
        {"x": 4.25, "y": 2.25},
        {"x": 3.25, "y": 3.25},
    ]
}
sock.sendall((json.dumps(data1) + "\n").encode())
print("发送: ", json.dumps(data1))

# 发送第二个目标（同一红色目标，不同位置）
time.sleep(0.5)
data2 = {
    "tx": -0.73,      # 微调位置（距离 < 0.08m，不会新增）
    "ty": 0.27,
    "tn": "red",
    "planner": [
        {"x": 0.25, "y": 0.25},
        {"x": 1.25, "y": 0.25},
    ]
}
sock.sendall((json.dumps(data2) + "\n").encode())
print("发送: ", json.dumps(data2))

# 发送第三个目标（不同颜色）
time.sleep(0.5)
data3 = {
    "tx": 0.25,
    "ty": 0.75,
    "tn": "blue",
    "planner": []
}
sock.sendall((json.dumps(data3) + "\n").encode())
print("发送: ", json.dumps(data3))

sock.close()
```

#### 方法 2：使用 netcat 发送

```bash
# 终端窗口1：启动地面站（连接 mock TCP server 或真实机载端）

# 终端窗口2：手动发送 JSON
```

## 四、附录

### A. 修改机载端 IP 地址

如果你的机载计算机 IP 不是 `192.168.10.3`，修改 `land_screen.py`：

```python
# 第 44 行，原内容:
SERVER_IP = "192.168.10.3"

# 改为你的实际 IP:
SERVER_IP = "192.168.1.100"  # 示例
```

或者通过环境变量设置（需要添加代码支持）。

### B. 日志文件位置

地面站会将所有检测到的目标写入 `web_groundstation/log.txt`：

```
格式: x坐标,y坐标,目标名称
示例:
-0.75,0.25,red
0.25,0.75,blue
```

### C. 多浏览器同时访问

地面站 Web 服务支持多个浏览器同时连接，每个浏览器窗口通过 WebSocket 独立接收实时数据。
适合场景：一个人操作主界面，另一个人查看目标信息。

### D. 浏览器兼容性

| 浏览器 | 支持 | 备注 |
|--------|------|------|
| Chrome / Edge | ✅ 完全支持 | 推荐 |
| Firefox | ✅ 完全支持 | |
| Safari | ✅ 支持 | Canvas 可能有细微差异 |
| IE11 | ❌ 不支持 | Socket.IO 不兼容 |

### E. 服务端口冲突处理

```bash
# 如果 5000 端口被占用，换一个端口:
python3 app.py --port 8080

# 查看哪些端口被占用:
ss -tlnp | grep -E "5000|8001"
```

### F. 启动顺序总结

```
真机部署:
   先 → 机载端 LandScreenNode (TCP 8001)
   后 → 地面站 python3 app.py
   后 → 浏览器 http://IP:5000

独立测试:
   先 → python3 mock_tcp_server.py (模拟 TCP 8001)
   后 → python3 app.py --server-ip 127.0.0.1
   后 → 浏览器 http://127.0.0.1:5000
```

> **核心原则：TCP 服务器 (端口 8001) 必须先于地面站客户端启动。**  
> 顺序反了也没关系，地面站会自动每 0.5 秒重连，等服务就绪后自动连上。
